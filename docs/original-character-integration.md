# 原创 Live2D 角色 B：安装版接入与验收

工作跨越 2026-11-11 至 2026-11-12。当前为个人自用的基础角色接入阶段，不是完整表情或物理建模完成证明。

## 实际接入方式

源码在 `desktop/packages/stage-ui/src/stores/display-models.ts` 增加「聆泊 · 原创角色 B」预设，同时保留 Hiyori。模型 ZIP 和透明预览位于 `desktop/packages/stage-ui/src/assets/live2d/models/lingbo-original-b.zip` 及对应预览目录；发布检查仅放行这个明确的原创 ZIP，其他 SDK 和第三方模型仍受原有检查限制。素材不随代码的 MIT 许可证自动授权，见第三方及素材说明。

日常安装版采用现有「设置 → 角色模型 → 选择模型 → 导入 → Live2D」入口导入相同 ZIP，并在界面中重命名为「聆泊 · 原创角色 B」、确认选用。没有为接入角色而替换安装版的整套渲染代码或后端。此前登录防护修复仍保留。

安装版原有的模型选择器、模型 ZIP 校验与 IndexedDB 存储负责保存模型；活动角色卡负责持久化模型引用。源码预设与安装版导入记录的 ID 不同，但模型内容相同。导入原 ZIP 的 SHA256 为 `94e171c5d2671fbb03fba30167f484e5b9a0eb7042d6b0525e7fd6dd313494f7`。

## 复用的真实驱动链路

```text
正常对话入口
  → Stage.vue 的 onBeforeMessageComposed
  → setupLipSync / setupAnalyser，连接语音输出
  → 当前 TTS 提供商通过本机网关合成
  → BrowserPlayback 实际播放，触发 onPlaybackStart / onPlaybackEnd
  → createLive2DLipSync 分析播放音频
  → character-speaking.mouthOpenSize
  → Model.vue 的 useMotionUpdatePluginLipSync
  → ParamMouthOpenY
```

模型的 EyeBlink 组包含 `ParamEyeLOpen` 和 `ParamEyeROpen`，LipSync 组包含 `ParamMouthOpenY`。自动眨眼与嘴部开合复用现有插件，没有新增第二条独立播放链路。当前是音频强度驱动的单轴嘴部开合，不是逐音素的多嘴形同步。

验证脚本若直接调用 `voice.startResponse` 而未经过对话初始化，不会自动完成 Stage 的嘴型分析初始化。本次隔离测试曾发现这一测试入口问题，已改用正常对话入口；不能把这种绕过初始化的失败当作实际产品链路失败。

## 会话问题须独立记录

重启后聊天窗口选中了一个较早的「新建对话」。测试文本保留在输入框，点击发送后网关的 LLM / TTS 请求计数仍为 0。切换到本次创建的验收会话后，相同文本成功进入模型并播报。

这说明该次失败发生在请求进入网关之前，不能归因于原创模型或 TTS。仅凭当时现象不足以定位原因，角色初次接入时也没有把会话兼容候选加入安装版。2026-11-12 随后在最新冷备份副本中重现历史语音附件解码错误，完成最小兼容补丁部署；用户复测反馈语音正常、嘴型跟随。详见 `docs/session-recovery-compatibility.md`。没有删除旧会话，也没有自动重放未发送草稿。
