# 对话与已有工作任务的上下文衔接

日期：2026-11-16。对应 0.3.7 的后台修复。

## 触发与根因

用户在角色对话中解释报价对比任务，角色却再次索要具体报价数字。实际检查发现：同一会话下的后台任务仍为暂停、版本 1，两份上传资料存在，进度接口可以读取任务及资料清单。

此前前台模型提示包含通用工作工具说明，但没有自动附带该会话已有任务的索引。桥接通知只在完成、失败、中断或需要确认时触发，不会把新建后暂停的任务自动介绍给前台角色。模型需要自行决定查询已有任务；这次回答没有利用到后台资料信息。文件存在和会话关联正确，本身不足以保证自然对话能够接上任务。

## 修复内容

`backend/work-chat-context.mjs::workChatContext` 在每一次前台模型请求时生成当前会话的有界任务索引，包含任务编号、状态、版本、要求摘要、来源编号和文件名、产物数量和名称。优先显示执行中或尚未完成的任务；云端最多 3 项、本地模型最多 1 项，分别限制在 3800、1600 字符内。

`backend/server.mjs` 仅在前台模型分支调用它，按认证请求的会话筛选，不使用全局活动会话代替请求归属。工作进程不注入该索引；后续工具步骤再次经过模型入口时重新生成，避免缓存旧版本。

指引要求涉及已有任务时使用 `lingbo_work_control` 查询真实状态，再回答或调整；摘要未包含原文并不表示资料没有上传。摘要不会加入报价原文、任意路径、目录授权、凭据或新操作权限，也不能作为读取正文或完成任务的证据。

原始要求、文件名和产物名以 JSON 数据表示，作为历史数据而非当前操作指令。该处理不构成抵抗所有提示注入的证明。摘要本身不调用控制工具、不创建任务、不恢复暂停任务、不替代具体确认。修改仍受原有任务状态、版本、文件哈希、确认卡与执行回执机制约束。

## 验证

- 139 项后端自动化测试通过。新增检查覆盖会话隔离、版本刷新、上下文预算、名称保持为 JSON 数据，以及实际网关把最新任务摘要送入模型请求的行为。
- 网关路由夹具替换外部模型为回显，仅用于观察转发内容；不计作真实模型任务成功。
- 真实 DeepSeek 的 3 个固定案例通过：自然询问“什么工作任务”时调用进度工具并解释已上传报价；从新对话直接修改“清单放开头、先不要执行”时先查询完整任务，保留两项输出约定并更新到版本 2，任务仍暂停且没有启动工作进程；其他会话没有获得该任务资料。
- 真实案例使用合成任务元数据，模型返回和实际工作控制接口未被替换。没有将这些案例等同于完整桌面语音、全文分析或产物生成验收。

测试不证明模型在每次自然表达下都会选择正确工具。真正的执行边界仍由后端状态检查和具体确认机制承担；真人语音任务联动仍需完成。

构建、升级及本机数据保留结果另存本地忽略目录 `artifacts/release-0.3.7`。Vivi 女声使用已有本机音色配置，不随本次后台代码更新重置。

## 本机交付结果

0.3.7 已完成本机升级。495 项安装载荷源文件哈希与包内清单一致，7 项已有配置文件（包括本机音色配置）与升级前一致；旧配置副本和安装版的 18 个会话、当前会话 316 条消息的内容哈希，以及角色素材哈希均一致。正常退出后可重新启动。

通过实际安装版网关，在带有“还未提供数字”这一旧错误回答的合成对话中重新询问“什么工作任务”，真实模型调用进度工具取得原暂停任务及两份报价清单。检查过程中原任务仍保持暂停、版本 1，尝试次数和回执数量未变。该检查没有向桌面会话写入测试消息，也没有替用户修改任务。

这是安装版网关的文字查询回归，不能记作已经完成真人麦克风任务控制。安装版已重新打开供继续验收；没有推送 GitHub。
