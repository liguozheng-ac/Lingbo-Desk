# 日常安装版服务配置恢复与登录请求循环

日期：2026-11-17。对象：桌面快捷方式指向的 0.3.7 安装版，不是独立工作台演示环境。

## 现场事实

用户报告启动后回到 Hiyori，文本请求返回 DeepSeek 凭据未配置，展开角色菜单时出现大量“本地版本未启用账号登录服务”的提示。

只读检查确认：快捷方式指向既有安装目录，包清单版本为 0.3.7；日常数据目录缺少 `services.dpapi`、`settings.json`、`speech-voice.json` 与 `profile-migration.json`。此前升级备份仍有这些文件。没有证据能确认文件缺失的起因，不能归因于某次升级、用户操作或安全软件。

此前真实文档演示使用独立后端与数据目录，且复用加密配置副本。该成功不能证明日常安装版配置完整。

## 恢复范围

在确认安装程序已停止后，对日常角色配置做冷备份，再从已有升级备份恢复上述四个文件。凭据继续使用 Windows 当前用户 DPAPI 加密，不写入源码，不回显，不覆盖聊天、记忆、任务或资料目录。恢复后的服务配置没有解密警告。

正式安装版重启后：DeepSeek 单次真实文本请求返回 10；ASR 鉴权及会话建立检查成功；TTS 短句合成取得音频字节。后两项分别不代表识别准确率、麦克风或实际播放验收。

## 登录请求循环

已有主进程防护会拒绝未配置的账号登录，不打开授权浏览器；现场仍观察到角色菜单持续产生拒绝提示。共享认证状态的 `requestLogin`、`consumeLoginRequest` 与 `expireSession` 没有按桌面本地模式抑制请求，因而主进程拒绝本身不足以阻止提示循环。最初由哪个业务模块触发请求，尚未唯一定位。

`desktop/packages/stage-ui/src/stores/auth.ts` 增加本地模式开关：桌面只有显式构建启用账号服务才允许请求；本地模式会清除待登录标记，消费请求返回 false，会话过期仍清理认证状态但不再发起登录。Web 与显式账号模式保留原有单消费者及会话版本逻辑。

`backend/test/local-account-mode.test.mjs` 执行源码中的三个实际方法，覆盖 500 次重复请求与过期标记消费、旧会话版本、凭据清理及账号模式行为，3 项通过。没有以请求次数换算真实稳定性。

当前安装版仅对已有渲染模块应用等价的本地构建补丁；9911 个包内文件逐一比对，仅该文件变化，49 个原生解包文件的内容与分类保持。原包已留存，可回退。没有重新发布完整安装器或推送 GitHub。

使用设置窗口 File → Exit 正常退出，确认安装程序进程退出后从正式可执行文件启动。原创角色自动恢复，最终比例与位置保留；三项服务配置仍存在，角色心跳恢复，configurationRequired 为 false。此前一次重启后正式网关真实问答再次返回 10。主角色菜单曾展开观察，未再出现此前连续刷出的登录拒绝提示；最终重启画面的可见拒绝提示计数为零。这是本机有限观察，不是长时稳定性或所有账号流程验收。

## 自动发送现场复查（同日）

用户报告每次语音停留在草稿，必须手动发送。设置窗口实际显示“自动发送”已经开启，延迟为 0.5 秒，输入模式为持续聆听，但麦克风总开关关闭。因此不能将根因确定为“没有开启自动发送”。通过已有 UI 将自动发送关闭再开启，延迟调整为 0.7 秒，并开启麦克风；保留原有说完判定与转写改写设置。没有修改语音代码，也没有声称已证明跨窗口状态同步故障。

复查时主角色窗口再次为空白、网关显示角色离线；通过工作台菜单正常退出，确认安装版进程数为零后重新启动。主角色恢复原创外观并显示“正在听”，网关显示角色连接和三项服务凭据就绪。该空白问题尚未定位，正常重启恢复不等于修复渲染稳定性。

源码 `desktop/packages/stage-ui/src/composables/voice-drafts.ts` 的 `acceptSpeech()` 在每条新提交到达时读取自动发送设置；已存在的旧草稿不会因设置变化自动补发。`sendDraft()` 的提交失败也会保留草稿，单凭草稿界面无法区分未自动发送与发送失败。目前已请求用户用一条新语音、完全不点击发送按钮验收；在收到结果前，以上仅证明设置已调整、聆听与连接恢复，不证明自动回复故障已经解决。
