# 连续语音与打断复查

日期：2026-11-17 至 2026-11-18。对象：日常 0.3.7 安装版。

## 现场及证据边界

用户首先确认无需点击草稿即可回答，随后报告下一句需重开麦克风。在保持麦克风开启的复现中，用户反馈前两句能回答，之后不识别、不能插话；进一步描述为上一句结束后需要等几秒再说。不能把这些反馈简化为“每一轮都关闭了麦克风”。

新增 `desktop/bridges/renderer-voice.mjs` 的 `listener.health` 低频诊断，每 5 秒读取已存在的麦克风帧坐标、VAD 窗口计数、输入阶段、播报标记、浏览器回声消除标记及占用状态。仅在正在聆听时上报，不保存音频、转写正文、设备 ID 或凭据。`backend/voice-metrics.mjs` 对上述字段显式筛选，内存环形数组仍上限 1500 条。短音段取消仅映射固定状态 `speech-too-short`，不向后端转发任意错误正文。

现场诊断显示麦克风帧与 VAD 窗口持续增长，检测更新间隔正常，浏览器报告回声消除开启，未见录音附件或其它采集租约占用。已结束的输入没有一直挂在 controller 上。一次短语输入约 121 ms 的语音片段后取消；此前默认 `minSpeechMs` 是 300 ms，但这只是时序关联，旧记录未保留取消原因，不能确定该次取消就是短音段过滤。没有证据支持“麦克风每轮必然断流”。

## 两处可证实的问题与修改

### 1. Silero ONNX 输入上下文

`desktop/packages/stage-ui/src/workers/vad/silero-vad-model.ts::score()` 原先直接把每个 512 点窗口送入 ONNX，只保留循环状态。Silero 官方 ONNX 包装器在 16 kHz 下会把上一窗口末尾的 64 个采样点前置，形成 576 点输入，同时维护循环状态。

源码证据：[Silero 官方 `OnnxWrapper.__call__`](https://github.com/snakers4/silero-vad/blob/master/src/silero_vad/utils_vad.py)。新增每个实例独立的 64 点上下文；首窗为零，成功推理后更新为当前窗口末尾；音频间断时上下文和循环状态一起重置。保留既有 32 ms 外部窗口、VAD 阈值、短语过滤和回声门控，不通过关闭回声抑制来实现插话。

原生 ONNX 测试使用现有合成语音 PCM，间隔静音重复 5 次。原输入方式和补齐上下文的方式都能检测这段合成语音，因此没有复现“第三轮必然失效”，不能把格式缺陷直接认定为全部用户现象的唯一原因。候选包实际模型类再对照 64 点上下文参考实现，895 个窗口、5 次重复的概率结果最大差为 0；这只证明候选适配器计算一致，不是麦克风识别或打断成功率。

### 2. 缓冲式识别无法提前完成说完判定

当前本机 `openai-compatible-audio-transcription` 路径在 `hearing.ts::createTranscriber()` 中先通过 `encodeWav()` 收集整段音频，再上传识别。在录音结束前没有中间文本。此前 `voice.ts::startListening()` 只要启用说完判定，就在 1.2 秒停顿上无条件增加 3 秒宽限；而判断模型需要读取转写文本，无法在这个上传路径上提前结束录音。

修改为：只有启用判定且当前输入已有非空中间转写时，才保留原有宽限；没有中间转写时按已有的 1.2 秒停顿结束录音。流式识别有中间文本时继续保留判断能力。不承诺端到端响应为 1.2 秒，上传、ASR、文字改写、聊天模型与 TTS 仍各有耗时。没有新增每轮主动重开麦克风的逻辑。
