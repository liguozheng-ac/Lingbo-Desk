# 任务工作台实施和验证记录

日期：2026-11-12 至 2026-11-13（Asia/Shanghai）。本轮是 HR 展示准备的一个阶段，不是安装版或公开仓库的新版本发布。

## 实现范围

新增 `/workspace` 任务工作台，保留原管理页。从原管理页可进入工作台。提供资料选择、双语报告要求、历史任务、真实执行阶段、来源快照、具体动作确认、暂停、修改、恢复、取消，以及产物正文预览和下载。没有增加模拟任务结果、虚拟百分比、外部统计服务或新的模型服务。

提交资料时继续复用 `SourceBundles` 的原件保存、正文提取与完整性检查。`work-sources.mjs` 将带 `S1-P1` 等段落编号的提取正文写入当前工作任务的 `output/inputs`，并保存原件与快照哈希。工作进程获得的是任务内的文本快照，不是私有来源存储目录的访问权限。普通文件工具不能写入这些输入快照；每次运行及查看快照前检查哈希与路径链接。此限制属于工具策略，不是针对任意本地脚本的操作系统沙箱。

上传不授予整个目录权限：工作台显式提交 `rootIds: []` 和 `skillIds: []`。使用云模型时，被读取的正文会发送给该模型服务，页面已提示。源文档是不可信资料；提示词约束不能被解释成已证明抵抗所有提示注入。

## 实际调用关系

1. `workspace.mjs` 在点击提交时捕获当前已连接桌面对话的会话 ID。无角色连接时使用工作台独立会话。
2. `/sources/import` → `SourceBundles.import` 导入选择的文件。
3. `/work/submit` → `WorkService.create` → `loadWorkSources` / `writeWorkSources` → 原有独立 Agent 工作进程。
4. Worker 的真实 `work_*` 工具调用仍经过认证的执行代理、目录策略、具体确认与回执。
5. `work_finish` 使用原有的 `verifyAcceptance` 检查两项声明的输出文件。本工作台只预设文件路径，没有预设业务正文或语义评分。
6. 工作台轮询 `/status` 和 `/work/status`。`workspace-view.mjs` 依据成功回执与最终核验结果构建显示信息；不会把模型的“已完成”文字当成进展证据。

关键新增或修改文件：

| 文件 | 责任 |
| --- | --- |
| `backend/workspace.html` | 工作台布局、表单与对话框 |
| `backend/workspace.mjs` | 会话绑定、上传、状态刷新、任务控制、批准、预览和下载 |
| `backend/workspace-view.mjs` | 由真实状态与回执生成显示模型；双语报告任务模板 |
| `backend/work-sources.mjs` | 验证并建立编号资料快照；查看与重运行前验证 |
| `backend/work-service.mjs` | 来源接入现有任务；快照返回请求 ID 以恢复提交结果 |
| `backend/work-policy.mjs` | 禁止普通写工具改动上传快照 |
| `backend/work-tools.mjs` | 覆盖创建 Word 时的确认信息补充拟写入全文 |
| `backend/server.mjs` | 工作台静态入口及带任务会话检查的来源接口 |

## 并发与状态处理

上传开始后即使用户切换桌面对话，该次提交仍属于点击时的会话。选中历史任务后，控制、批准、来源和下载请求使用该任务的所属会话。批准按钮绑定已显示的任务 ID、版本和批准 ID，后台仍验证当前有效性。修改和取消对话框同样捕获目标，避免刷新后误操作另一任务。

工作台保存未确认提交的请求 ID；刷新时先在后台快照中查找已接收任务，重试复用原请求 ID。底层 `WorkService.create` 保留原有按会话和请求 ID 去重的行为。连接中断时显示“上次已知状态”，禁止新的执行操作，恢复后重取真实状态。界面不是任务执行所有者，关闭页面不会被当作取消任务。

## 验证结果

### 自动化检查

- 最终后端测试：131 项通过、0 失败。包含 4 项新增工作台/来源测试，以及 Word 覆盖确认必须包含正文预览的新增断言。
- 浏览器：6 组交互检查，使用本地夹具服务及真实页面脚本，没有调用模型。覆盖跨会话确认、HTML 文本不执行、暂停改版与恢复、断线禁用、上传期间切换会话、提交响应丢失与刷新去重、来源查看、产物预览及实际字节下载、窄屏无横向溢出。
- `check:source` 和 Git 空白检查另行记录；不把源码扫描当作功能验收。

复现命令：安装项目和 desktop 开发依赖后，运行 `npm test` 以及 `node scripts/verify-workspace.mjs`。浏览器脚本需要已安装 Chrome，或通过 `LINGBO_TEST_CHROME` 指定测试浏览器；可以通过 `VOICE_PYTHON` 指向具备项目依赖的 Python。测试脚本仅操作临时夹具。

### 真实模型业务案例

使用 [中文报价](demo-inputs/供应商甲-中文.md) 和 [日文报价](demo-inputs/供应商乙-日本語.md)，由真实 DeepSeek、真实独立工作进程和真实工具完成。没有使用真实业务文件或外部账户，没有增加任何目录授权。

最终录制案例：版本 1 生成初稿后暂停，修改至版本 2，恢复并取得 11 次具体修改批准；共留下 23 条工具回执，最终生成 Word 和 Markdown 两份实际文件。独立检查了：

- 上传原件 SHA256 未改变。
- 当前版本包含实际文件修改回执，两项声明产物通过原有文件/哈希验收。
- Word 正文包含独立计算的 `20000 + 800 = 20800`，中文和日文均解释运费税费口径未明确；实际出现的来源编号存在于快照。
- 11 份修改备份分别匹配对应路径此前记录的文件哈希。
- 来源接口无凭据被拒绝，其他会话不能读取该任务的来源。
- 从界面下载的 Word 字节与任务目录内文件 SHA256 一致。

以上是固定小样本的检查，不是整体语义评分、日文翻译准确率或 Word 排版验收。录制约 153 秒，包含为了看清页面而设置的停留和逐项确认时间，**不能作为后台任务纯耗时、响应延迟或吞吐量统计**。没有可靠的任务成功率或每任务成本数据。

## 发现的问题及处理

1. **内容推定过度**：首轮把设备与运费之和称为含税总额，但原文只明确设备含税。保留失败线索，使用暂停、补充完整要求和恢复进行纠正；没有删改原资料来迁就输出。这说明来源编号存在不等于引用蕴含关系正确。
2. **Word 确认信息不完整**：覆盖创建 Word 的旧确认仅含路径、哈希和创建结果。补充 `contentPreview`，展示拟写入全文，配合具体文件与哈希检查；已有精确替换继续显示前后文本。增加实际工具测试断言。
3. **提交重试与会话漂移**：浏览器可能重试连接断开的请求，上传期间也可能切换会话。通过固定提交会话、既有后端去重及请求结果恢复处理；浏览器检查包含这些场景。
4. **浏览器测试的异步等待**：产物预览通过异步请求加载。测试先读取旧对话框文字曾产生误报，已改为等待新预览对话框出现；未把测试等待问题记为产品成功。
