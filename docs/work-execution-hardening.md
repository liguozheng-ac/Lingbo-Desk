# 工作执行边界与文件验收加固

日期：2026-11-04。基线：`c807dfdf2f551f649e333a4e91af0e6548dab40f`。

后续更新：2026-11-05 将 DOCX 本地正文验收上限扩为 1000000 字符，并修正旧浏览器模式断言；本记录中的 60000 字符与失败断言描述保留为当时基线，现状见 [长文档与故障恢复](long-documents-and-recovery.md)。报告导入的 60000 字符限制仍保留。

本次修复三个已复现的问题：未暴露给模型的工具仍可能被调用；调用预算在串行分支不构成硬上限；任意成功修改的回执不能证明指定产物符合要求。

## 变更机制

### 执行白名单

`engine/src/runtime/tool-execution-boundary.js` 在执行器入口之前检查工具名。

- 模型调用必须具有本轮已加载的工具 schema。
- 通用引擎保留可信 `find_tool` 返回结果加载 schema 的机制。
- 后台工作由 `backend/work-finalize.mjs` 固定允许的 `work_*` 名单，不随模型输出扩展。补交回执只允许 `work_finish`。
- `backend/work-service.mjs` 再独立检查工作工具名单，不能用 broker 调用原生命令、安装工具或自行批准操作。
- 引擎自行产生的确认提示、最终投递也经过同一边界；通用会话可进行内部 `send_message` 投递，固定工作名单不开放此例外。

这不是操作系统沙箱。用户批准的 Skill 脚本仍具有当前用户权限，单个脚本内部的行为不受工具名称白名单限制。

### 实际调用预算

`createToolExecutionBudget()` 使用私有计数器，并在任何异步操作之前同步预占额度。

- 串行、并行、跨模型轮次、失败的已派发调用均占额度。
- 白名单拒绝和预算拒绝不会进入执行器，不算已派发调用。
- 主执行与补交回执共享总预算，补交不会获得新的 48 次额度。
- 工作默认每次运行最多 48 次实际派发，主流程最多 45 次，预留最多 3 次交验收回执。若主流程正常完成，不必使用补交。
- broker 另有每次运行 48 次的检查，包含失败、重复动作回执查询和 `work_finish` 请求；成功验收之后禁止新动作。
- 手动恢复会启动新 attempt 和新预算；历史动作及幂等检查继续保留。上限不是任务整个生命周期的永久总数，也不是 Token 或费用上限。

### 固定产物条件

`backend/work-acceptance.mjs` 接收提交任务时确定的 `acceptance`，仅在安全暂停后修改任务时允许更改，并递增版本。`work_finish` 不能覆盖这些条件，也不能提供自制的验收结果。

每项条件包含：

```json
{
  "path": "总结.docx",
  "contains": ["项目结论"],
  "notContains": ["待补充"]
}
```

可另提供已知的 `sha256`。相对路径在提交时固定为该任务的绝对产物路径。最多 8 个文件、每种文本条件最多 8 项，合计有长度限制。任务台可直接填写一个文件条件；语音工具及本地 API 支持多文件数组。

验收时，服务依次检查：

1. 当前目录授权仍有效。
2. 指定目标存在当前任务版本的成功文件动作回执，读文件或改另一个文件不能代替。
3. 文件实际 SHA256 与回执一致，并匹配可选预期哈希。
4. 直接读取目标内容，检查精确包含/不包含条件。
5. 提取完成后再次检查授权、取消状态及哈希，拒绝验收期间发生变化的文件。

文本检查读取完整文本，超过 1000000 字符则拒绝，不用截断内容验收；支持 UTF-8/GB18030。DOCX 使用现有提取器重新打开文件，检查正文段落和表格，最多 60000 字符；不检查页眉页脚、图片、批注、版面或隐藏对象。XLSX/PPTX 等目前可检查目标和哈希，正文条件会明确失败，不以局部读取结果冒充全量验收。单文件继续受 20 MB 限制。

没有提供条件的旧任务仍可执行，结果明确标记 `verification.scope=execution_only`。提供条件并通过则标记 `declared_outputs`，附检查范围及限制。删除、网页状态变化和脚本业务效果尚无通用可执行验收器；相关回执不等于业务结果正确。自然语言修改关键词判断仍只是补充拦截，不能覆盖所有意图。

本次测试均使用临时资料、确定性模型或本地 SSE。没有真实云端模型成功率、语音表现或用户文档变更的统计。
