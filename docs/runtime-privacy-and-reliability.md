# 工作进程、诊断日志与异常收尾

日期：2026-11-04。本轮接续[执行边界加固](work-execution-hardening.md)，仅修改本地源码及隔离验证副本，未发布 GitHub、构建安装包或更新已安装应用。

## 修复的问题与取舍

| 已确认的问题 | 本轮处理 | 主要取舍 |
| --- | --- | --- |
| 通用工作与报告进程直接继承 `process.env` | 统一使用环境变量白名单，清空 Node 继承启动参数 | 这些进程通过本机网关访问模型；不支持再隐式读取主进程的云端密钥或代理凭据 |
| stdout/stderr、事件日志、turn trace 和部分诊断数据库可能重复保存正文 | 新文件只保存固定状态及计数；默认停止新增全文诊断记录 | 诊断细节减少，业务回执与检查点仍保留 |
| 原有 worker 退出等待没有统一保证，取消可能等待模型超时 | 统一等待进程及标准输出管道关闭，超时升级终止；生命周期统一收尾 | 强制终止不会撤销已发生操作，也不提供跨进程事务 |
| 进程清理尚未完成就删除引用或发布完成状态 | 完成状态延后；清理失败保留引用，阻止恢复和模型切换 | 清理失败会表现为中断，需要检查，不能假装已经安全停止 |

## 凭据与环境边界

`runtime/worker-environment.mjs::workerEnvironment()` 仅保留 PATH、Windows 系统与用户目录、临时目录和必要语言时区变量。调用方只能额外传入明确列出的网关地址、本机连接令牌、任务编号、任务票据、隔离数据目录及输出预算。未知字段直接报错。

不会继承云端 API Key、任意 Secret、自定义环境变量、`NODE_OPTIONS`、`NODE_PATH` 或带凭据的代理变量。`runtime/worker-process.mjs::startWorker()` 还设置 `execArgv: []`，避免继承父进程的 Node 预加载/调试启动参数。通用工作和报告使用同一规则。文档提取/Office Python 助手及独立 Edge 启动也使用过滤后的环境；Python 保留明确的 UTF-8 输出设置。

云端模型密钥仍由网关主进程持有。工作进程仍持有必要的本机网关令牌与任务票据；这不是进程用户权限隔离，也不能防止已获系统权限的恶意程序从本机文件、进程或网络中获取数据。网关连接令牌还不是每任务最小权限的模型令牌，这项边界仍可继续收紧。

## 新诊断日志

`runtime/diagnostic-log.mjs::DiagnosticLog` 在 `.local/diagnostics` 创建带版本头的新文件。

- 事件先经 `diagnosticMetadata()` 投影，只留下固定事件类型、有限状态、时间、退出码、字节/调用计数等字段。请求、文件正文、模型输出、工具参数、自由文本错误及路径不会写入该日志。
- worker 的 stdout/stderr 持续被读取，只汇总字节数和块数；不会把原始输出拼接或保存，因此跨块凭据也不会进入日志。
- 每个活动文件最多 256 KiB，保留一份同等大小的轮转备份。目录保留最近 16 个受管理文件，清理超过 7 天或数量上限的非活动文件；活动写入及其备份不被清理。新日志创建/关闭时检查数量和年龄，不是定时后台清理服务。
- 清理仅处理固定文件名、普通文件及正确版本头同时匹配的受管理日志，不递归删除目录，不清理旧 `runtime.log`、`events.jsonl`、任务状态、数据库、备份或产物。
- 活动文件被替换、出现未知备份、单条元数据无法满足上限或写盘失败时，停止写入该日志并标记 `failed`，避免覆盖未知数据；这项诊断写入失败不会中断业务工作。

网关实时 SSE 仍发送界面所需的任务快照，但使用 `createSecretRedactor()` 对已知凭据、敏感字段和常见密钥形态脱敏。磁盘诊断与界面事件分开，避免为了精简日志而删掉界面需要的任务信息。脱敏不能自动识别一切个人信息或任意格式秘密。

应用网关与新 worker 默认设置 `LINGBO_DIAGNOSTICS_METADATA_ONLY=1`：

| 代码位置 | 效果 |
| --- | --- |
| `engine/src/runtime/turn-trace.js::beginTurn` | 不再创建新的全文回合追踪；已有文件不改写 |
| `engine/src/db.js::insertActionLog` | 默认不新增可能含参数与结果正文的诊断行动日志 |
| `engine/src/db/repositories/brain-ui-events.js` | 默认不新增持久化脑图事件正文；即时事件仍可在内存转发 |
| `engine/src/db/repositories/audits.js` | 默认不新增 recall/extract 的诊断正文 |

**这些规则不等于“应用不保存正文”。** 聊天数据、任务 JSON、执行所需数据库、工具回执、明确记忆、资料快照、备份和产物仍可包含正文。它们是功能数据，不会按诊断日志规则自动清除。已有历史诊断数据保持原样，未扫描或删除用户真实历史记录。

## 进程收尾与任务状态

`startWorker()` 创建子进程后立即监听错误、IPC 与 `close`。`done` 以 `close` 为准，包括标准输出管道关闭，而不只依赖 `exit`。

`stop()` 可重复调用且共享正在进行的停止流程。先发 `shutdown`，默认等待 3 秒；未关闭时，在 Windows 用本次创建的 PID 执行 `taskkill /T /F`，Unix 使用独立进程组，再等待确认关闭。关闭失败会抛出错误；再次清理可以重试。IPC 已关闭时发送命令返回 false，不因“再次取消”引发未捕获异常。

通用工作 `WorkService.run()`：

1. 初始化本次 controller、票据、计数，并清除上次 `stopAs`，避免恢复后仍继承旧暂停结果。
2. 启动超时默认 30 秒，总执行期限仍为 20 分钟。
3. 完成、失败、崩溃、超时和用户中止均进入同一收尾路径。
4. 先撤销 broker 票据、发送 abort，再等待 worker 关闭、已进入的工具结束及工具资源清理。
5. 工具/资源清理分别有等待上限；未清理完时保留引用或在途标记，标为中断，不能启动同任务的新 attempt 或切换模型。残留 worker/工具也计入工作并发限制。
6. 动作已经启动而缺少完整回执，继续保留 `intent/uncertain`。恢复仍要求人工核对，不自动重放不确定操作。

报告 `WorkerClient` 使用相同 supervisor。取消时启动退出流程，不再仅等模型请求自行结束；只有 worker 确认关闭后才发布正常完成状态。报告和通用工作仍是两套状态机，本轮没有宣称完成全局任务调度重构。

关服务时两套任务并行收尾；清理失败不会记为正常退出。

## 验证及边界

环境：本机 Windows、Node 24.22.1；Office 测试使用现有 Python 3.12.14 文档运行时。测试资料位于临时目录，凭据为合成值；未调用真实云端模型、语音服务或外部账户，未占用 WPS。

| 检查 | 结果与范围 |
| --- | --- |
| `node --test backend/test/*.test.mjs` | **83/83 通过**。包含原有 69 项及新增 14 项；验证实际 fork 的环境、秘密脱敏、日志大小/数量/年龄、保留旧文件、不响应关闭及其测试后代进程、启动失败、暂停/恢复/取消、等待确认时中止、崩溃时工具中止、期限超时、清理失败时禁止恢复 |
| `node scripts/verify-task.mjs` | 真实网关、独立工作进程、文件工具和正文验收通过；模型为本地固定响应 |
| `node scripts/verify-report.mjs` | 真实报告进程完成提取、生成及检查点；另一个报告任务取消成功；新诊断日志未出现测试报告正文 |
| `node scripts/verify-diagnostic-privacy.mjs` | 实际 SQLite 的 4 类诊断表未增加正文记录；旧行和旧 trace 保留 |
| `node scripts/verify-tool-boundaries.mjs` | 上轮 8 个真实循环边界场景继续通过；模型和执行器为受控测试替身 |

原有 `test-action-contract.js` 的“大浏览器”分类断言失败已在上一轮以基线复现，参见前一份记录；本轮未把它计为通过，也未改动该功能。

仍需关注：

- Windows 尚未使用 Job Object；父进程已先行消失时，不能承诺清理任意脱离的后代进程。测试证明的是被跟踪且仍存活的 worker 及其测试后代。
- Skill 脚本仍具有当前用户权限；脚本自行启动/脱离的进程和独立浏览器全生命周期不在本轮端到端保证范围内。未启动真实 Edge 做页面操作验证。
- 已完成文件动作不回滚，强制中止也不能证明任意外部操作没有发生。
- 默认精简诊断会损失全文排障信息；需要进一步设计显式、限时且经过脱敏的调试模式。
- 日志 `failed` 标记目前供内部诊断使用，尚未做日志写盘失败的界面提醒。
- 本轮通过的是隔离验证，不代表真实模型成功率、长时间稳定性、延迟或安装包升级已得到重新验证。

详细日志及验证副本的 SHA256 同步记录保存在本地审计目录中；原有审计报告作为历史基线保留。
