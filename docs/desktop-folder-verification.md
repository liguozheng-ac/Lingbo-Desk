# 桌面文件夹直接读取：实机验证

日期：2026-11-18。对象：日常 0.3.7 安装版、真实 DeepSeek 模型与实际 Agent 工作进程。本次只做功能验证，没有修改产品源码、原资料或已有用户文档，也没有上传 GitHub。

## 测试入口与授权

在桌面新建专用演示文件夹，写入两份完全虚构的中日文 TXT 报价。通过现有文件授权接口，只对该文件夹授予 `read` 权限；没有授予整个桌面访问或写入权限。输入分别为 539 字节、716 字节，包含原币价格、数量、税费缺失项、运费、交期和付款比例，未提供跨币种换算汇率。

从实际角色的文字聊天框提交自然语言要求：按准确绝对路径读取两份资料，比较条款，列出风险和待确认事项，保留来源，生成 Word 与 Markdown，附日文摘要，并保持原资料不变。没有使用工作台上传、来源快照导入或由 Codex 代写最终报告。

## 真实执行链与结果

聊天 UI 可见 `Lingbo submit work`，随后后台完成通知触发 `Lingbo work control` 查询。后台任务 `work-628360c8-e1f7-479e-9b3d-358ee7115ebd` 达到 `completed`，`inputSources` 为空；成功回执包括：

1. `work_list` 列出授权资料目录。
2. 两次 `work_read` 读取实际桌面文件，回执 SHA256 与输入清单一致。
3. `work_office` 创建 DOCX。
4. `work_write` 创建 Markdown。
5. `work_list` 检查产物。

工具调用计数为 7（包括完成控制调用），可列出的成功执行回执为 6；不能把两者当成独立任务数。两份原资料在执行前后 SHA256 相同。Word 和 Markdown 均实际存在，主要金额、币种、来源编号与资料一致；日文摘要位于 Markdown 中。角色在查询完成状态后才向聊天反馈已完成。

这证明准确路径和具体文件夹授权下，可以通过聊天让 Agent 直接读取桌面资料并生成产物。没有验证模糊文件名搜索整个桌面、自动发现桌面路径、鼠标打开文件或本次语音下达指令。

## 内容与展示质量问题

- 跨币种推断有一处不严谨：报告因 B 的尾款比例为 70%、A 为 50%，推断 B 的尾款金额更大。缺少汇率时只能比较比例，不能据此比较实际金额。虽然主体结论正确提醒币种不可直接比价，这处句子仍需人工复核。
- 在 WPS 打开真实 DOCX，状态栏显示 8 页。首张来源表的第一列过窄，中文出现逐字换行；长 SHA256 放入表格也影响版面。文件生成成功不等于达到演示排版要求。
- WPS 显示缺少 Courier 字体的替换建议；没有执行替换或保存修改。
- WPS 打开 DOCX 后会产生 `~$` 锁文件；现有任务产物枚举暂未排除此类文件。本次验证只将实际 DOCX 与 Markdown 计为两项产物。

桌面读取及文件交付链路通过；正式 HR 演示产物仍需先改善表格排版与跨币种结论复核。没有把这轮验证表述为完整业务正确率或所有文档格式通过。原始输入清单与执行核对保存在 Git 忽略目录 `artifacts/desktop-folder-demo-2026-11-18`，含本机路径的记录不发布。
