# 本地版登录反复拉起浏览器：修复记录

2026-11-11。该问题在原创 Live2D 接入测试之后、启动日常安装版并操作角色控制栏时暴露。

后续状态：修复已纳入 0.3.5 统一构建，安装升级及真人验收见 [版本记录](release-0.3.5.md) 和 [验收记录](acceptance-0.3.5.md)。后文的最小补丁及待接入状态属于当时的阶段记录。

## 已查证的事实

- 一次本机异常中，安装版主进程重复启动了 239 个 Chrome 浏览器进程，目标均为本机语音网关的 `/api/auth/oauth2/authorize`；另有 237 个 Chrome 崩溃报告子进程。公开记录省略具体进程号及系统事件时间。
- 同次 Windows System 日志的 Application Popup 事件明确记录“虚拟内存不足”，随后出现 `0xc000012d` 和 `0xc0000142` 等启动错误。不能用事后空闲内存较多否认当时的资源耗尽。
- 安装包编译代码确认：账号服务默认 URL 指向本机网关；`createAuthService` 的登录入口每次取消旧尝试后重新创建授权流程，并调用 `shell.openExternal`。窗口导航保护也会将 HTTP 授权地址交给系统浏览器。
- 本机语音网关没有提供这些 OIDC 账号端点，本地语音、角色、文件工作无需账号登录。
- 首次登录请求究竟来自控件点击、待消费的登录状态还是其他请求触发，现有记录不足以唯一定位；没有为了复现而再次实际启动大量浏览器。

因此本次修复覆盖两个能启动浏览器的入口，并在已配置账号服务的模式中防止同一窗口反复替换正在进行的登录。它不是对首次触发源已完全还原的声明。

## 修复

- `desktop/apps/stage-tamagotchi/src/main/services/lingbo/auth.ts`：本地构建默认禁用账号登录；没有 `VITE_ENABLE_ACCOUNT_LOGIN=true` 时返回明确错误，不打开浏览器、不创建回调监听、不请求账号服务。启用账号服务时，同一窗口的进行中请求复用原尝试，保留跨窗口显式替换及旧回调隔离规则。
- `desktop/apps/stage-tamagotchi/src/main/windows/shared/window.ts`：未启用账号服务时，不将回环地址的 `/api/auth/` 导航或弹窗交给系统浏览器；普通帮助链接仍可正常打开。
- `desktop/apps/stage-tamagotchi/src/renderer/components/stage-islands/controls-island/controls-island-auth-button.vue`：进行中请求不重复提交；IPC 失败时退出加载状态，允许用户重试。
- `docs/setup.md`：说明本地模式与可选 OIDC 服务的构建配置区别。

## 清理范围

仅清理进程快照中父 PID、创建时间、可执行路径均匹配此次异常的 476 个进程。逐个再次核对创建时间，避免 PID 复用导致误杀。没有删除浏览器资料、修改虚拟内存设置或清理后来新开的浏览器进程。

## 验证

1. 3 个相关测试文件共 23 项测试通过，无未处理异常。新增覆盖未启用账号时的重复请求、进行中请求去重、按钮 IPC 失败恢复，以及本地授权页导航/弹窗拦截。
2. 完整桌面构建通过，源码发布检查通过。
3. 从实际安装包候选中提取编译函数，在受控 Electron 适配器下分别执行 500 次登录请求、500 次本地授权导航、500 次本地授权弹窗：授权浏览器打开次数、网络请求及回调监听数均为 0；普通外部帮助链接仍可通过。按钮 500 次调用只发起 1 次进行中 IPC。
4. 上述重复调用测试不是真实浏览器、账号登录或系统压力测试。
5. 安装版修复后启动，角色窗口和服务端口出现。运行时观察没有发现由本次聆泊实例创建的 Chrome 进程。设置窗口完整交互和真实账号流程未作为通过项。

## 安装版最小修复与回退

为避免将其他尚未部署的开发改动一并带入，只对原安装包做本地构建等价修复：修改主进程编译模块及控制栏所在渲染模块，共 2 个文件。

- 核对包内 9909 个文件，其余文件内容一致；49 个原生解包文件的分类和内容保持一致，因此没有替换原生依赖目录。
- 原安装包已备份；替换前核对散列、确认程序未运行，替换后再次核对。
- 没有迁移、重写或替换用户会话、模型选择及服务凭据。正常启动仍会产生应用自己的运行日志。
- 原包 SHA256：`d8ece2ad51cd01271bcd9599854a92462d8d6960a4629170dd753e039690c9db`。
- 修复包 SHA256：`10b477f47c3bd00d2b4f292e968c819f70febf1ed7c8b54eb6f0d4e18191b2fe`。
- 回退应先正常退出程序，再将本机证据目录 `installed-before/app.asar` 恢复到程序资源目录；旧包仍包含该缺陷，不建议在未防护的情况下再次触发登录。

本机详细证据位于被 Git 忽略的 `artifacts/auth-loop-2026-11-11/`：清理目标、测试日志、候选逐文件验证、编译函数验证、部署及启动记录。没有保存完整授权 URL、账号令牌或用户消息正文。

本次安装版修复不包含此前的会话兼容候选或原创角色新增预设。原创角色在源码及隔离桌面中的既有测试结果保留，日常安装版导入及真实语音验收仍待继续。
