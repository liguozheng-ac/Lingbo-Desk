## 实际失败链

```text
voice-drafts.ts::acceptSpeech / sendDraft
  → chat.ts::submit / prepareSend
  → session-store.ts::loadSession
  → chatSessionsRepo.getSession
  → extractInlineChatAssets
  → chatAssetIdFrom 未识别历史引用
  → decodeBase64 / InvalidCharacterError
  → loadSession 返回 false
  → 上层提示无法加载目标会话，保留草稿
```

安装版编译代码也已只读核查，确认上述加载函数及错误检查存在，不只依据当前源码推断。

## 修复范围

- `desktop/packages/stage-ui/src/libs/chat-asset-reference.ts`：解析当前及历史本地附件引用。历史格式限定为有界命名空间及 64 位十六进制内容编号，不接受 URL、路径或任意数据库名称。
- `desktop/packages/stage-ui/src/libs/chat-assets.ts`：旧引用继续作为引用处理；读取历史附件时走对应的兼容读取入口。
- `desktop/packages/stage-ui/src/database/repos/chat-assets.repo.ts`：只读打开已存在的历史附件库，检查附件记录类型；不迁移、重写或删除旧附件和 owner 列表。
- `backend/test/chat-asset-compatibility.test.mjs`：针对历史引用识别、普通 Base64 不误判、缺失数据库、枚举/打开竞争及存储失败进行验证。

读取时数据库若已消失，会中止建库升级，避免误创建空库。无法读取的附件继续明确报错，不静默替换为空会话。

未修改任务调度、模型路由、自动发送开关或工具确认规则。本轮没有改动最初怀疑的会话初始化逻辑，因为副本回放已找到更直接的附件兼容原因。
