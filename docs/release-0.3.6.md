# 0.3.6 统一展示入口与交付验证

日期：2026-11-16（Asia/Shanghai）。目标是将角色与新工作台放入同一套 Windows 应用，避免日常版和独立联测角色的入口混淆。本记录不代表真人语音任务联动已经验收。

## 使用方式与生命周期

启动聆泊后，原角色与内置任务工作台使用同一个应用实例和本机后端。托盘菜单新增“任务工作台”；重复点击入口或再次启动程序，复用同一工作台，不重复创建角色或后端。

工作台原生菜单“聆泊”中提供“显示角色与语音入口”和“退出聆泊（关闭全部窗口与后台）”。快捷键为 Ctrl+Q。关闭工作台窗口仍可从托盘重新打开；完整退出使用菜单或托盘的退出项。

原有服务配置页仍能通过工作台进入。工作台关闭、重新打开或应用重启不会被当作新的任务提交。

## 实现依据

- `desktop/launcher/workspace-window.mjs::createWorkspaceWindow` 管理原生工作台的单窗口和打开过程，限制导航到当前本机网关，拒绝外部窗口和 webview。窗口禁用 Node，启用上下文隔离和 sandbox；没有给默认 Electron session 设置权限处理器，避免影响角色麦克风。
- `desktop/launcher/package-bootstrap.mjs` 在后端与角色启动后打开工作台，并处理 `lingbo:open-workspace` 和 `second-instance`；菜单完整退出进入现有后端及窗口清理流程。
- `desktop/apps/stage-tamagotchi/src/main/tray/index.ts` 在打包启动器存在时提供工作台入口。
- 打包配置显式包含新启动器模块及工作台后端文件；载荷检查覆盖新界面、来源快照及相关策略模块。
